NagaraAI — Multi-Channel Intake

Implementation guide · November 2026 · 75 tests passing 9 channels IBM watsonx.ai

1. What Was Built

NagaraAI now accepts civic complaints from 9 external channels in addition to the web portal. Citizens can report issues by texting WhatsApp, sending an SMS/MMS, calling a voice number, messaging on Telegram, Facebook, Instagram, Twitter/X, or emailing — in any language, with photos, videos, or voice recordings. Every inbound message is automatically classified by IBM watsonx.ai Granite-13B (falling back to a local rule-based classifier) and an acknowledgement is sent back on the same channel.

4. The Central Dispatcher — How It Works

backend/app/channels/dispatcher.py is the single function every webhook handler calls. It is channel-agnostic: it takes a normalised set of fields and handles everything else.

1
AI Classification
Calls classify_with_watsonx(text). If WATSONX_API_KEY is set, it hits the IBM watsonx.ai Granite-13B model. Otherwise it runs the local keyword-based fallback. Returns category, priority, confidence, summary.
2
Persist InboundMessage
Writes the message to the inbound_messages table including all AI fields. Uses db.flush() to get the new ID before inserting child records.
3
Persist MediaAttachments
Loops over the attachments list. Each item needs {media_type, url}. media_type can be an enum value or a plain string — both are accepted.
4
Send Acknowledgement
Fires an async _send_ack() which picks the right outbound sender for the channel. Errors in ack sending are logged as warnings and never raise — they don't fail the main pipeline. Voice channel skips this step (send_ack=False) because TwiML already plays a <Say>. 
msg = await dispatch_inbound(
    db=db,
    channel=ChannelType.whatsapp,
    sender_id="+919876543210",
    raw_text="Garbage pile near MG Road bus stop",
    attachments=[{"media_type": "image", "url": "https://…/photo.jpg"}],
    metadata={"MessageSid": "SM1234"},
)

5. Channel Adapters

💬 WhatsApp — whatsapp.py

Uses Twilio WhatsApp Business API. Inbound webhook is form-encoded. Signature verified via HMAC using TWILIO_AUTH_TOKEN. Set TWILIO_VERIFY_SIGNATURE=false for local dev.

📱 SMS / MMS — sms.py

Also uses Twilio. Same signature verification flow. Auto-detects MMS when NumMedia > 0. MMS media URLs extracted by index (MediaUrl0, MediaUrl1…).

📞 Voice — voice.py

Returns TwiML on inbound call: greets in English (Indian accent), records up to 120 seconds with Twilio transcription enabled. Transcription is POSTed to /webhook/voice/transcription.

✈️ Telegram — telegram.py

Telegram Bot API. Webhook secured with X-Telegram-Bot-Api-Secret-Token header. Supports photos (largest size), video, audio, document. File IDs stored as tg://file/<id> URIs.

📧 Email — email_chan.py

Outbound via SMTP (TLS). Inbound via JSON webhook (compatible with SendGrid Inbound Parse / Mailgun). Also includes an RFC 2822 raw email parser for direct MTA integration.

👍 Facebook — social.py

Meta Graph API webhooks. Subscription verified via GET hub challenge. Inbound payload verified with HMAC-SHA256 (X-Hub-Signature-256). Outbound via /me/messages.

📸 Instagram — social.py

Identical webhook format to Facebook. Uses separate META_IG_ACCESS_TOKEN for outbound DMs. Shares the same META_VERIFY_TOKEN for hub challenge.

🐦 Twitter/X — social.py

Account Activity API (v2). Inbound tweet events parsed from tweet_create_events. Outbound DMs use OAuth1 via requests-oauthlib.

All adapters are safe to run unconfigured. Every outbound sender checks for required credentials first and logs an info-level skip instead of raising. This means tests run with zero external credentials and production can enable channels one by one.

8. Frontend Changes

ReportModal.js — Channel Selector

A new 📡 Reporting Channel dropdown was added to the complaint submission form. Options: Web (default), WhatsApp, Telegram, SMS, Email. When a non-web channel is selected, a contextual hint appears explaining how to report directly via that channel instead.

The channel field is currently informational — it records how the citizen intends to interact. For programmatic multi-channel filing, use the webhook endpoints directly.

ComplaintDetail.js — Send Notification Panel

Officers (field_officer / ward_officer / commissioner) now see a 📣 Send Notification button on each complaint detail view. Clicking it expands an inline panel with:

  • Channel toggle buttons: WhatsApp, SMS, Telegram, Email
  • Recipient input (auto-labelled: phone/email/chat_id depending on selected channel)
  • Send button that calls POST /api/channels/dispatch
  • Toast notification on success or failure

10. Deploying a New Channel

1
Set the credentials — add the relevant env vars to your .env or Kubernetes secret.
2
Expose the webhook URL — in development, use ngrok http 8000 to get a public HTTPS URL. For Telegram run POST /api/channels/telegram/set_webhook once after deploy. For Meta/Twitter, register the URL in their developer portals.
3
Register your webhook — point the platform's dashboard at https://your-domain/api/channels/webhook/<channel>.
4
Test end-to-end — send a test message on the channel and verify a row appears in GET /api/channels/inbound.
Twilio signature verification: Set TWILIO_VERIFY_SIGNATURE=true in production. For local dev with ngrok, set it to false otherwise the HMAC will mismatch because the URL seen by Twilio differs from what your server computes.
